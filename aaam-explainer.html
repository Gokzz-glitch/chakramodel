AAAM

AQI Prediction Dashboard

Automated Air-quality Alert & Monitoring

An AQI monitoring and forecasting workbench powered by Amazon Chronos-2, with explicit safeguards around uncertainty and hardware control.

What is AAAM?

AAAM combines live Open-Meteo readings, historical AQI context, a pretrained time-series model, and a dashboard for alerts. It is a working local prototype; it does not yet operate a purifier or promise a calibrated prediction.

📡

Data Fetch

Reads current US AQI, PM2.5, and PM10 from Open-Meteo for the selected coordinates. “Live” means provider data fetched by the browser, not a private sensor stream.

🧠

ML Inference

Feeds historical data into the Amazon Chronos-2 Time-Series model.

📊

Forecasting

Requests between 1 and 14 forecast steps. The current backend uses hourly history; the UI presents a seven-value outlook, so do not interpret each value as a guaranteed calendar day.

⚠️

Spike Detection

Scores predicted exceedance of the configurable AQI 150 threshold. This is a heuristic risk score, not a calibrated probability of a future event.

🌬️

Actuation

Defines a device-command boundary, but the current endpoint returns published: false. MQTT/TLS publishing and physical actuation are planned, not enabled.

Premium Tech Stack

Built with modern, lightweight, and high-performance technologies.

⚛️ Frontend

React 19 & Vite 8 with Vanilla CSS. A 27KB design system featuring Pure SVG charts and Glassmorphism.

⚡ Backend

FastAPI & Uvicorn running on Python 3.12 for lightning-fast asynchronous endpoint resolution.

🤖 Chronos-2 + PyTorch

Chronos-2 is the pretrained time-series model that learns patterns in the AQI history and generates possible future values. PyTorch is the numerical runtime that stores the history as tensors, runs the model, and performs the median calculation. AAAM asks for 64 model samples and returns their median as the point forecast. PyTorch runs on CPU or a compatible GPU; it is the engine, not a separate forecasting model.

☁️ Data Source

Open-Meteo Air Quality API. 100% free, requiring no API key for historical and current data.

🖥️ Infrastructure

WSL2 Ubuntu backend bridged natively with a PowerShell orchestrator script for Windows hosts.

✨ Design

DM Sans & Manrope fonts, deep dark themes, backdrop blurs, and scroll-triggered animations.

Data Flow Step-by-Step

Data Collection

In API mode the backend requests up to 14 past days of hourly us_aqi values, roughly 336 points. It rejects a response with fewer than 48 usable observations. In hardware mode it keeps at most 336 AQI samples per device in memory and needs at least 48 samples; that buffer is lost when the process restarts.

# API Call
GET https://air-quality-api.open-meteo.com/v1/air-quality
  ?latitude=13.08
  &longitude=80.27
  &hourly=us_aqi
  &past_days=14

ML Inference (Chronos-2)

Chronos-2 is the forecasting model; PyTorch is the runtime underneath it. The backend converts the hourly AQI list into a PyTorch tensor, sends it through the configured amazon/chronos-2 pipeline, requests 64 possible trajectories, and takes the median at each step. This reduces the effect of an unusually high or low sample, but it is still model output—not a guarantee—and calibrated confidence intervals are not currently returned.

from chronos import Chronos2Pipeline
import torch

pipeline = Chronos2Pipeline.from_pretrained("amazon/chronos-2", device_map="auto")
context = torch.tensor(history) # hourly AQI values

# The API currently requests 1–14 forecast steps; the UI sends 7.
samples = pipeline.predict(context, prediction_length=7, num_samples=64)
median_forecast = samples.median(dim=0).values

Spike Detection

The system compares predictions with AAAM_SPIKE_THRESHOLD, which defaults to 150. It uses recent-history baseline and forecast exceedance magnitude to produce a bounded score from 0.01 to 0.99. The API calls this a probability, but the score has not been statistically calibrated.

score = clamp(exceedance / (steps × max(10, 150 − recent_mean)), 0.01, 0.99)

REST API Endpoints

GET /health

Service health check. Reports the configured model, whether the lazy model cache is loaded, the selected source, and hardware-device count; it does not force model loading.

POST /api/forecast

Run a forecast with latitude, longitude, and horizon (1–14 model steps). A model/provider failure returns HTTP 503 with an explicit error.

POST /api/telemetry

Validate and append one AQI telemetry sample, with optional PM2.5, PM10, and timestamp, to the device's in-memory context buffer.

POST /api/source

Switch backend mode between 'api' and 'hardware'.

POST /api/devices/command

Validate a purifier command and return it as accepted. The current implementation deliberately reports published: false; no broker or purifier is contacted.

# Forecast request: horizon is model steps (1–14), not automatically days
POST /api/forecast
{"latitude": 13.0827, "longitude": 80.2707, "horizon": 7}

# Select hardware only after telemetry exists
POST /api/source
{"source": "hardware", "device_id": "sensor-01"}

# Successful forecast response includes these fields
{"model": "amazon/chronos-2", "forecast": [ ... ],
 "spike_probability": 0.42, "spike_threshold": 150,
 "history_points": 336, "input_source": "api"}

Beginner to Professional Guide

What the numbers mean, how to operate the prototype, and what must be added before a production safety system.

Beginner: what is AQI?

AQI is an index that summarizes pollution into an easier scale. AAAM displays US AQI and also shows PM2.5 and PM10 when the provider supplies them. A larger number means worse air; 150 is the current AAAM spike threshold, not a universal medical boundary.

Beginner: what happens?

Select a location, let the dashboard fetch a live reading, then wait for the backend to load Chronos-2 on the first forecast request. The API path supplies history; Hardware mode accepts repeated POST /api/telemetry samples.

Intermediate: source modes

API mode uses Open-Meteo history and coordinates. Hardware mode uses the first registered in-memory device history and falls back to the provider if it has fewer than 48 samples. Restarting the backend clears telemetry.

Intermediate: alerts

Alerts are shown only after a successful model response. Provider errors, missing hardware context, and model-load failures remain explicit; baseline placeholder values must not create a purifier alert.

Professional: validate forecasts

Backtest by time-splitting the PrimeOxy workbook and external observations. Measure MAE/RMSE, threshold precision and recall, false-alert rate, latency, missing-data behavior, and calibration of the spike score before operational use.

Professional: production gate

Add durable telemetry storage, device authentication, AWS IoT Core MQTT/TLS, signed and idempotent commands, acknowledgements, retries, stale-data fail-safe behavior, manual override, monitoring, access control, and a calibrated uncertainty policy. None of those production controls are complete in this prototype.

Important scope note

The supplied PrimeOxy AQI workbook has not yet been fully normalized into the live forecasting pipeline. Current API forecasts use Open-Meteo history; current hardware forecasts use telemetry posted to this process. “Powered by Chronos-2” identifies the model, not a guarantee of forecast accuracy.

How to Run

One Command (Recommended)

# Run the PowerShell orchestrator
.\start_aaam.ps1

# API will be available at: http://127.0.0.1:8000
# Dashboard will open at: http://localhost:5173
# Press Ctrl+C to gracefully stop all services.

Manual Execution

# Terminal 1 (WSL - Backend)
source .venv-aaam/bin/activate
uvicorn aqi_backend.main:app --host 0.0.0.0 --port 8000

# Terminal 2 (Windows - Frontend)
cd frontend
npm run dev
