What is AAAM?

A seamless pipeline that bridges real-world weather data, advanced Time-Series ML, and actionable hardware commands. It monitors air quality and predicts dangerous spikes days in advance.

📡

Data Fetch

Pulls real-time AQI data from the Open-Meteo API automatically.

🧠

ML Inference

Feeds historical data into the Amazon Chronos-2 Time-Series model.

📊

Forecasting

Predicts AQI levels accurately for the next 1 to 14 days.

⚠️

Spike Detection

Calculates the probability of AQI crossing the dangerous >150 threshold.

🌬️

Actuation

Commands smart air purifiers via MQTT/API when risk is high.

Data Flow Step-by-Step

Data Collection

The backend calls the Open-Meteo API retrieving 14 days of hourly AQI readings (~336 data points). A minimum of 48 points is required for a reliable context window.

# API Call
GET https://air-quality-api.open-meteo.com/v1/air-quality
  ?latitude=13.08
  &longitude=80.27
  &hourly=us_aqi
  &past_days=14

ML Inference (Chronos-2)

The history tensor is passed into the Chronos-2 pipeline. 64 sample trajectories are generated, and the median is taken as the final robust prediction.

from chronos import ChronosPipeline
import torch

pipeline = ChronosPipeline.from_pretrained("amazon/chronos-t5-small")
context = torch.tensor(history) # 336 hourly values

# Generate 64 samples for the next 7 days (168 hours)
samples = pipeline.predict(context, prediction_length=168, num_samples=64)
median_forecast = samples.median(dim=0).values

Spike Detection

The system compares the forecasted trajectory against the danger threshold (AQI > 150). It calculates the exceedance magnitude to return a probability.

P(Spike) = (Count(AQI > 150) / Forecast_Horizon) * 100%

Dashboard Display

The React frontend consumes the API payload and renders the SVG forecast charts, status panels, and alerts banner based on the spike probability.

REST API Endpoints

GET /health

Service health check. Verifies Chronos model is loaded and WSL is responsive.

POST /api/forecast

Run AQI forecast. Requires payload with latitude, longitude, and horizon (days).

POST /api/telemetry

Ingest hardware sensor readings directly into the ML context buffer.

POST /api/source

Switch backend mode between 'api' and 'hardware'.

POST /api/devices/command

Send actuation commands to registered air purifiers (e.g. {"action":"turn_on","fan_speed":"high"}).

Startup Sequence

What happens when you run start_aaam.ps1

1 Check WSL Ubuntu
2 Install Node Modules
3 Create .venv-aaam
4 Install PyTorch/FastAPI
5 Start Backend (:8000)
6 Health Check Loop
7 Start Frontend (:5173)
8 Dashboard Ready

How to Run

One Command (Recommended)

# Run the PowerShell orchestrator
.\start_aaam.ps1

# API will be available at: http://127.0.0.1:8000
# Dashboard will open at: http://localhost:5173
# Press Ctrl+C to gracefully stop all services.

Manual Execution

# Terminal 1 (WSL - Backend)
source .venv-aaam/bin/activate
uvicorn aqi_backend.main:app --host 0.0.0.0 --port 8000

# Terminal 2 (Windows - Frontend)
cd frontend
npm run dev
